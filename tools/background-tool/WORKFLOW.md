# Approved Background Tool workflow
Applications register/update/unregister rules when their own features require them (notification enabled or feature saved/activated). One API for all applications. Registration is independent of UI lifetime. Background Tool continuously evaluates rules using Data Tool demand/cache only; no direct ECU reads. Invalid or stale data must not trigger actions. Each rule declares inputs, freshness, conditions, trigger and one or more actions. Notification requests go to Notification Tool; other actions require explicitly approved, bounded adapters and authorization. No arbitrary executable payload. A new app must not disrupt existing rules. Durable registrations and state, recovery, diagnostics, bounded resources and versioned API are required for runtime readiness. Test independently before migrating apps. Never claim vehicle verification without evidence.

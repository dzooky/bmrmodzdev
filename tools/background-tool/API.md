# Background Tool API v1 (internal runtime draft)
The runtime request method takes a trusted owner supplied by a future authenticated transport, never by the client request. REGISTER/UPDATE/UNREGISTER/STATUS use lowercase op names and api:1. Register and update accept a rule with appId, ruleId, fields [{name,freshnessMs}], condition (numeric comparison eq/ne/gt/gte/lt/lte or nested all/any), trigger rising/once and actions [{type,name,payload}]. Unregister accepts ruleId. Identical registration preserves state. Changed rule resets state. Once means registration lifetime; drive reset is not implemented. Initial true may fire. Invalid input does not reset state. Persistent state is committed before dispatch: ambiguous failures are not automatically retried and a crash may lose an action. Actions are injected trusted adapters only; no arbitrary commands. Runtime uses Data Tool catalog and passive snapshots with lease renewal; unsupported fields remain unevaluable. Current Data Tool public API exposes raw numbers, not engineering units. No public registration socket or production action handlers yet.
